Spring Stack Report

What your Spring app runs on, what blocks the next upgrade, what is vulnerable — every finding linked to its line.

How it works

The data, and how fresh it is

Nothing about your project is stored. Each time you analyze it, the appliance reads it where it lives: a GitHub repository at the commit its branch or tag points to now (cloned once, then kept by commit — a commit never changes), or a folder of yours, read afresh every time. Its Java source and its application settings are parsed in place; its Maven build is resolved by Maven's own resolver, every module against the others, against Maven Central. Support dates come from spring.io and endoflife.date (cached a day); advisories from deps.dev and the fixed versions from OSV (cached a day, a week for a published version). Which properties Spring Boot binds, deprecates and removed comes from the configuration metadata inside Spring Boot's own jars, for the version you run and the version you upgrade to. Your decisions in the debt inbox are the one thing kept, as SpringTriage entries in your world.

Every view, with the Cypher that runs

ProjectOverview — What a project is: the commit or folder read, its modules, and how many types, source files, settings and dependencies it has. The first call for any project, and proof the key resolves.
MATCH (p:JavaProject {key: $project})-[:HAS_MODULE]->(m:ProjectModule)
WITH p, collect(m.coordinates) AS modules, head(collect(m.project)) AS read
OPTIONAL MATCH (p)-[:DECLARES_TYPE]->(t:JavaProjectType)
WITH p, modules, read, count(t) AS types
OPTIONAL MATCH (p)-[:HAS_SETTING]->(s:ProjectSetting)
WITH p, modules, read, types, count(s) AS settings
OPTIONAL MATCH (p)-[:DEPENDS_ON]->(d:ProjectDependency) WHERE d.depth > 0
RETURN read AS project, modules, size(modules) AS moduleCount, types, settings,
       count(DISTINCT d.coordinates) AS dependencies
StackCard — What a Spring project runs on: its Spring Boot and Spring Framework versions, the Boot line and when that line's open-source and commercial support end, the Java versions the line supports, its latest patch, and the newest Spring Boot line. The first call for a Spring project.
MATCH (p:JavaProject {key: $project})-[:DEPENDS_ON]->(d:ProjectDependency)
WHERE (d.groupId = 'org.springframework.boot' AND d.artifactId = 'spring-boot')
   OR (d.groupId = 'org.springframework' AND d.artifactId = 'spring-core')
WITH collect(DISTINCT CASE WHEN d.artifactId = 'spring-boot' THEN d.version END) AS boots,
     collect(DISTINCT CASE WHEN d.artifactId = 'spring-core' THEN d.version END) AS cores
WITH [v IN boots WHERE v IS NOT NULL][0] AS bootVersion, [v IN cores WHERE v IS NOT NULL][0] AS frameworkVersion
WITH bootVersion, frameworkVersion, split(bootVersion, '.')[0] + '.' + split(bootVersion, '.')[1] AS line
MATCH (sp:SpringProduct {slug: 'spring-boot'})-[:HAS_GENERATION]->(g:SpringGeneration)
WITH bootVersion, frameworkVersion, line, sp, collect(g) AS gens, toString(date()) AS today
MATCH (sp)-[:HAS_CYCLE]->(c:SupportCycle)
WITH bootVersion, frameworkVersion, line, gens, today, collect(c) AS cycles
WITH bootVersion, frameworkVersion, line, today,
     [x IN gens WHERE x.name = line + '.x'][0] AS mine,
     [x IN cycles WHERE x.cycle = line][0] AS myCycle,
     reduce(n = null, x IN gens | CASE WHEN x.initialReleaseDate <= today
            AND (n IS NULL OR x.initialReleaseDate > n.initialReleaseDate) THEN x ELSE n END) AS newest
RETURN bootVersion, frameworkVersion, line + '.x' AS bootLine,
       mine.ossSupportEndDate AS ossSupportEnds, mine.commercialSupportEndDate AS commercialSupportEnds,
       CASE WHEN mine IS NULL THEN 'unknown'
            WHEN mine.ossSupportEndDate >= today THEN 'supported'
            WHEN mine.commercialSupportEndDate >= today THEN 'commercial-only'
            ELSE 'unsupported' END AS support,
       myCycle.supportedJavaVersions AS javaVersions, myCycle.latest AS latestPatch,
       newest.name AS newestLine, newest.ossSupportEndDate AS newestSupportEnds
BootLines — Every Spring Boot line: when its open-source and commercial support end, the Java versions it supports, and its latest patch — what to upgrade to, and what that asks of your Java.
MATCH (sp:SpringProduct {slug: 'spring-boot'})-[:HAS_GENERATION]->(g:SpringGeneration)
WITH sp, g, toString(date()) AS today
OPTIONAL MATCH (sp)-[:HAS_CYCLE]->(c:SupportCycle)
WHERE c.cycle + '.x' = g.name
RETURN g.name AS line, g.initialReleaseDate AS released, g.ossSupportEndDate AS ossSupportEnds,
       g.commercialSupportEndDate AS commercialSupportEnds, c.latest AS latestPatch, c.supportedJavaVersions AS javaVersions,
       CASE WHEN g.initialReleaseDate > today THEN 'upcoming'
            WHEN g.ossSupportEndDate >= today THEN 'supported'
            WHEN g.commercialSupportEndDate >= today THEN 'commercial-only'
            ELSE 'unsupported' END AS support
ORDER BY released DESC LIMIT 40
ModernizationFindings — Code Spring has moved past, in Java, Kotlin or Scala, from the realm's rule catalogue (reference/rules.yml — the SpringRule rows): javax packages Jakarta EE renamed, removed adapters, @MockBean, JUnit 4, Jackson 2 under Spring Boot 4, field injection and more. Each finding names its rule, the Spring Boot version it breaks in, the fix, the OpenRewrite recipe when one is verified, and Spring's documentation. With `target` (a Spring Boot version) it says which findings block that upgrade.
MATCH (r:SpringRule {kind: 'import'})
MATCH (p:JavaProject {key: $project})-[:IMPORTS_SOURCE]->(i:SpringImport)
// What is imported, in full: Java's rows name it (`name`); the other languages' say where from (`imported`).
WITH r, i, coalesce(i.name, i.imported) AS imported
WHERE imported STARTS WITH r.pattern AND NOT ANY(x IN coalesce(r.excludes, []) WHERE imported STARTS WITH x)
  AND (coalesce(r.appliesTo, 'all') = 'all' OR NOT i.path CONTAINS 'src/test/')
WITH r, i ORDER BY i.path, i.line
WITH r, collect(i) AS uses, collect(DISTINCT i.path) AS files
RETURN 'rule:' + r.ruleId AS id,
       r.severity AS severity, r.category AS category, r.title + ': ' + toString(size(uses)) + ' use' + CASE WHEN size(uses) = 1 THEN '' ELSE 's' END + ' in ' + toString(size(files)) + ' file' + CASE WHEN size(files) = 1 THEN '' ELSE 's' END
         + ' (' + reduce(t = '', f IN files[0..4] | t + CASE WHEN t = '' THEN '' ELSE ', ' END + split(f, '/')[size(split(f, '/')) - 1]) + CASE WHEN size(files) > 4 THEN ', …' ELSE '' END + ')' AS title,
       r.detail + CASE WHEN r.breaksIn <> '' AND $target <> '' AND [n IN [x IN split($target, '.') | toInteger(x)] WHERE n IS NOT NULL][0..2] >= [n IN [x IN split(r.breaksIn, '.') | toInteger(x)] WHERE n IS NOT NULL]
                       THEN ' Blocks the upgrade to ' + $target + '.' ELSE '' END AS detail,
       r.fix + CASE WHEN r.recipe <> '' THEN ' (OpenRewrite recipe ' + r.recipe + ')' ELSE '' END + '.' AS fix,
       uses[0].path AS file, uses[0].line AS line, coalesce(uses[0].link, uses[0].url) AS link, r.docs AS docs, r.ruleId AS rule, r.breaksIn AS breaksIn
UNION
MATCH (r:SpringRule {kind: 'file'})
MATCH (p:JavaProject {key: $project})-[:HAS_FILE]->(f:ProjectFile)
WHERE f.fileName = r.pattern AND f.path CONTAINS 'src/main/resources/META-INF/'
RETURN 'rule:' + r.ruleId + ':' + f.path AS id,
       r.severity AS severity, r.category AS category, r.title + ' in ' + CASE WHEN f.module = '' THEN 'the root module' ELSE f.module END AS title,
       r.detail + CASE WHEN r.breaksIn <> '' AND $target <> '' AND [n IN [x IN split($target, '.') | toInteger(x)] WHERE n IS NOT NULL][0..2] >= [n IN [x IN split(r.breaksIn, '.') | toInteger(x)] WHERE n IS NOT NULL]
                       THEN ' Blocks the upgrade to ' + $target + '.' ELSE '' END AS detail,
       r.fix + CASE WHEN r.recipe <> '' THEN ' (OpenRewrite recipe ' + r.recipe + ')' ELSE '' END + '.' AS fix,
       f.path AS file, 1 AS line, f.link AS link, r.docs AS docs, r.ruleId AS rule, r.breaksIn AS breaksIn
ModernizationFindingsInCode — The second half of ModernizationFindings: the rules that match an annotation, an injected field or a supertype, where that view has those that match an import or a file. Two views because each reads a whole project's rows of one kind, and a large project's imports and declarations together are more than one statement may bring in. Code Spring has moved past, in Java, Kotlin or Scala, from the realm's rule catalogue (reference/rules.yml — the SpringRule rows): javax packages Jakarta EE renamed, removed adapters, @MockBean, JUnit 4, Jackson 2 under Spring Boot 4, field injection and more. Each finding names its rule, the Spring Boot version it breaks in, the fix, the OpenRewrite recipe when one is verified, and Spring's documentation. With `target` (a Spring Boot version) it says which findings block that upgrade.
MATCH (r:SpringRule {kind: 'annotation'})
MATCH (p:JavaProject {key: $project})-[:DECLARES_SOURCE]->(a:SpringDeclaration)
// Only the kinds these annotations are written on are read: a filter on the row's own property
// is applied before rows are brought in, and a large project's every declaration is too many.
// A use-site target (`@field:MockBean`) is the same annotation.
WHERE a.kind IN ['class', 'object', 'interface', 'field']
  AND ANY(x IN a.annotations WHERE x = r.pattern OR x ENDS WITH ':' + r.pattern)
  AND (coalesce(r.appliesTo, 'all') = 'all' OR NOT a.path CONTAINS 'src/test/')
WITH r, a ORDER BY a.path, a.line
WITH r, collect(a) AS uses, collect(DISTINCT a.path) AS files
RETURN 'rule:' + r.ruleId AS id,
       r.severity AS severity, r.category AS category, r.title + ': ' + toString(size(uses)) + ' use' + CASE WHEN size(uses) = 1 THEN '' ELSE 's' END + ' in ' + toString(size(files)) + ' file' + CASE WHEN size(files) = 1 THEN '' ELSE 's' END
         + ' (' + reduce(t = '', f IN files[0..4] | t + CASE WHEN t = '' THEN '' ELSE ', ' END + split(f, '/')[size(split(f, '/')) - 1]) + CASE WHEN size(files) > 4 THEN ', …' ELSE '' END + ')' AS title,
       r.detail + CASE WHEN r.breaksIn <> '' AND $target <> '' AND [n IN [x IN split($target, '.') | toInteger(x)] WHERE n IS NOT NULL][0..2] >= [n IN [x IN split(r.breaksIn, '.') | toInteger(x)] WHERE n IS NOT NULL]
                       THEN ' Blocks the upgrade to ' + $target + '.' ELSE '' END AS detail,
       r.fix + CASE WHEN r.recipe <> '' THEN ' (OpenRewrite recipe ' + r.recipe + ')' ELSE '' END + '.' AS fix,
       uses[0].path AS file, uses[0].line AS line, uses[0].url AS link, r.docs AS docs, r.ruleId AS rule, r.breaksIn AS breaksIn
UNION
MATCH (r:SpringRule {kind: 'field-annotation'})
MATCH (p:JavaProject {key: $project})-[:DECLARES_SOURCE]->(a:SpringDeclaration)
WHERE a.kind = 'field' AND ANY(x IN a.annotations WHERE x = r.pattern OR x = 'field:' + r.pattern)
  AND (coalesce(r.appliesTo, 'all') = 'all' OR NOT a.path CONTAINS 'src/test/')
RETURN 'rule:' + r.ruleId + ':' + a.path + '#' + coalesce(a.owner, '') + '.' + a.name AS id,
       r.severity AS severity, r.category AS category, r.title + ': ' + last(split(coalesce(a.owner, ''), '.')) + '.' + a.name AS title,
       r.detail + CASE WHEN r.breaksIn <> '' AND $target <> '' AND [n IN [x IN split($target, '.') | toInteger(x)] WHERE n IS NOT NULL][0..2] >= [n IN [x IN split(r.breaksIn, '.') | toInteger(x)] WHERE n IS NOT NULL]
                       THEN ' Blocks the upgrade to ' + $target + '.' ELSE '' END AS detail,
       r.fix + CASE WHEN r.recipe <> '' THEN ' (OpenRewrite recipe ' + r.recipe + ')' ELSE '' END + '.' AS fix,
       a.path AS file, a.line AS line, a.url AS link, r.docs AS docs, r.ruleId AS rule, r.breaksIn AS breaksIn
UNION
MATCH (r:SpringRule {kind: 'extends'})
MATCH (p:JavaProject {key: $project})-[:DECLARES_SOURCE]->(t:SpringDeclaration)
// The supertype as the declaration writes it: `extends X` in Java and Scala, `: X()` in Kotlin.
WHERE t.kind IN ['class', 'object'] AND t.signature CONTAINS r.pattern
  AND (coalesce(r.appliesTo, 'all') = 'all' OR NOT t.path CONTAINS 'src/test/')
RETURN 'rule:' + r.ruleId + ':' + t.path + '#' + t.name AS id,
       r.severity AS severity, r.category AS category, t.name + ' ' + r.title AS title,
       r.detail + CASE WHEN r.breaksIn <> '' AND $target <> '' AND [n IN [x IN split($target, '.') | toInteger(x)] WHERE n IS NOT NULL][0..2] >= [n IN [x IN split(r.breaksIn, '.') | toInteger(x)] WHERE n IS NOT NULL]
                       THEN ' Blocks the upgrade to ' + $target + '.' ELSE '' END AS detail,
       r.fix + CASE WHEN r.recipe <> '' THEN ' (OpenRewrite recipe ' + r.recipe + ')' ELSE '' END + '.' AS fix,
       t.path AS file, t.line AS line, t.url AS link, r.docs AS docs, r.ruleId AS rule, r.breaksIn AS breaksIn
DocumentedSettings — Every configuration property the project's Spring jars document, once each by name, with its type and whether Spring Boot has deprecated it. Downloads the project's Spring jars the first time. One of the three inputs of the configuration check.
MATCH (p:JavaProject {key: $project})-[:HAS_JAR]->(j:ProjectJar)
WHERE j.jarPath IS NOT NULL AND (j.groupId STARTS WITH 'org.springframework' OR j.artifactId CONTAINS 'spring-boot'
   OR j.artifactId CONTAINS 'starter' OR j.artifactId CONTAINS 'autoconfigure')
MATCH (j)-[:DOCUMENTS]->(bp:BootProperty)
// A multi-module build reaches the same jar from every module: one row per property name.
WITH bp.name AS name, head(collect(bp)) AS bp
RETURN name, bp.type AS type, bp.deprecated AS deprecated, bp.deprecationLevel AS level,
       bp.deprecatedSince AS since, bp.deprecationReason AS reason, bp.replacement AS replacement
LIMIT 20000
SettingsWritten — Every setting the project's main resources write in application*.yml and .properties files: its key, its value, its file and line. Message bundles and logging files are left out. One of the three inputs of the configuration check.
MATCH (p:JavaProject {key: $project})-[:HAS_SETTING]->(s:ProjectSetting)
WHERE s.path CONTAINS 'src/main/resources' AND NOT s.path CONTAINS '/META-INF/'
  AND NOT s.fileName STARTS WITH 'messages' AND NOT s.fileName STARTS WITH 'logback' AND NOT s.fileName STARTS WITH 'log4j'
  AND NOT s.fileName STARTS WITH 'git.' AND NOT s.fileName STARTS WITH 'ValidationMessages'
  AND NOT s.name IN ['spring.config.activate.on-profile', 'spring.profiles']
RETURN s.name AS name, left(coalesce(s.value, ''), 300) AS value, s.path AS file, s.line AS line, s.link AS link
LIMIT 20000
SettingsReadByCode — The settings the project's own code binds, in Java, Kotlin or Scala: each @ConfigurationProperties and @Value as written, with its file and line. A setting under one of these is the project's own and is not Spring Boot's to document. One of the three inputs of the configuration check.
MATCH (p:JavaProject {key: $project})-[:DECLARES_SOURCE]->(d:SpringDeclaration)
WHERE NOT d.path CONTAINS 'src/test/'
  AND ANY(a IN d.annotations WHERE a = 'ConfigurationProperties' OR a ENDS WITH ':ConfigurationProperties' OR a = 'Value' OR a ENDS WITH ':Value')
UNWIND [t IN d.annotationText WHERE t CONTAINS 'ConfigurationProperties' OR t CONTAINS 'Value('] AS written
RETURN written, d.path AS file, d.line AS line
LIMIT 20000
UpgradeConfiguration — Settings in the project that the target Spring Boot version removed or renamed, each with the property to use there — read from the target release's own jars, which document every property they dropped with its replacement. `target` is a Spring Boot version, e.g. 3.5.16 or 4.1.2. Downloads the target's Spring Boot jars the first time.
MATCH (bom:BootBom {coordinates: 'org.springframework.boot:spring-boot-dependencies:' + $target})-[:PINS]->(v:BootManagedVersion)
WHERE v.groupId = 'org.springframework.boot' AND v.artifactId STARTS WITH 'spring-boot'
  AND NOT v.artifactId CONTAINS 'starter' AND NOT v.artifactId CONTAINS 'test' AND NOT v.artifactId ENDS WITH '-docs'
MATCH (v)-[:IS]->(b:BootJar)-[:DOCUMENTS]->(bp:BootProperty)
WHERE bp.deprecated
WITH collect(bp) AS dropped
MATCH (p:JavaProject {key: $project})-[:HAS_SETTING]->(s:ProjectSetting)
WHERE s.path CONTAINS 'src/main/resources' AND NOT s.path CONTAINS '/META-INF/'
  AND NOT s.fileName STARTS WITH 'messages' AND NOT s.fileName STARTS WITH 'logback' AND NOT s.fileName STARTS WITH 'log4j'
  AND NOT s.fileName STARTS WITH 'git.' AND NOT s.fileName STARTS WITH 'ValidationMessages'
WITH s, [x IN dropped WHERE toLower(replace(replace(x.name, '-', ''), '_', '')) = toLower(replace(replace(split(s.name, '[')[0], '-', ''), '_', ''))][0] AS match
WHERE match IS NOT NULL
RETURN 'upgrade-config:' + $target + ':' + s.path + ':' + toString(s.line) + ':' + s.name AS id,
       CASE WHEN match.deprecationLevel = 'error' THEN 'high' ELSE 'low' END AS severity,
       'upgrade-blocker' AS category,
       CASE WHEN match.deprecationLevel = 'error' THEN s.name + ' is gone in Spring Boot ' + $target
            ELSE s.name + ' is deprecated in Spring Boot ' + $target END AS title,
       coalesce(match.deprecationReason + '. ', '') + CASE WHEN match.deprecationLevel = 'error' THEN 'It no longer binds there: the setting is silently ignored.' ELSE 'It still binds, for now.' END AS detail,
       CASE WHEN match.replacement IS NOT NULL THEN 'Rename it to ' + match.replacement + '.' ELSE 'Remove it.' END AS fix,
       s.path AS file, s.line AS line, s.link AS link
LIMIT 500
Vulnerabilities — Security advisories affecting the exact versions the project resolves, worst first: the dependency, the advisory and its CVE ids, its CVSS score, and the fixed version on your own line (same major.minor) when there is one — else the nearest fix above it.
MATCH (p:JavaProject {key: $project})-[:DEPENDS_ON]->(d:ProjectDependency)
WHERE d.depth > 0 AND size(split(d.coordinates, ':')) = 3
WITH DISTINCT d.coordinates AS coordinates, d.version AS version, d.groupId + ':' + d.artifactId AS artifact, head(collect(d)) AS d
MATCH (d)-[:HAS_ADVISORY]->(a:DependencyAdvisory)-[:DESCRIBED_BY]->(x:AdvisoryDetail)
OPTIONAL MATCH (a)-[:FIXED_IN]->(f:AdvisoryFix)
WITH coordinates, version, artifact, a, x, collect(f.fixed) AS fixes,
     split(version, '.')[0] + '.' + split(version, '.')[1] AS line
WITH coordinates, version, artifact, a, x, fixes, line,
     [v IN fixes WHERE split(v, '.')[0] + '.' + split(v, '.')[1] = line][0] AS onLine
RETURN 'cve:' + coordinates + ':' + a.advisoryId AS id,
       CASE WHEN x.cvss3Score >= 9 THEN 'critical' WHEN x.cvss3Score >= 7 THEN 'high' WHEN x.cvss3Score >= 4 THEN 'medium' ELSE 'low' END AS severity,
       'vulnerability' AS category,
       artifact + ' ' + version + ': ' + x.title AS title,
       a.advisoryId + coalesce(' / ' + [y IN x.aliases WHERE y STARTS WITH 'CVE-'][0], '') + ', CVSS ' + toString(x.cvss3Score) AS detail,
       CASE WHEN onLine IS NOT NULL THEN 'Upgrade to ' + onLine + ' (same line).'
            WHEN size(fixes) > 0 THEN 'Fixed in ' + reduce(s = '', v IN fixes | s + CASE WHEN s = '' THEN '' ELSE ', ' END + v) + ' — no fix on your ' + line + ' line.'
            ELSE 'No fixed version is published yet.' END AS fix,
       coordinates AS file, 0 AS line, x.url AS link, x.cvss3Score AS cvss
ORDER BY cvss DESC LIMIT 500
VersionOverrides — Where the project's build pins a different version than the Spring Boot it runs would — a `<jackson-bom.version>` property, a hand-written version on a managed dependency — so a patch Spring Boot ships for it never arrives. Compared against the Spring Boot release's own BOM.
MATCH (p:JavaProject {key: $project})-[:DEPENDS_ON]->(boot:ProjectDependency)
WHERE boot.groupId = 'org.springframework.boot' AND boot.artifactId = 'spring-boot'
WITH p, head(collect(boot.version)) AS bootVersion
MATCH (bom:BootBom {coordinates: 'org.springframework.boot:spring-boot-dependencies:' + bootVersion})-[:PINS]->(v:BootManagedVersion)
WITH p, bootVersion, collect(v) AS pins
MATCH (p)-[:MANAGES]->(m:ProjectManagedVersion)
WITH bootVersion, m, [x IN pins WHERE x.groupId = m.groupId AND x.artifactId = m.artifactId][0] AS pin
WHERE pin IS NOT NULL AND pin.version <> m.version
WITH bootVersion, m.version AS mine, pin.version AS boots, collect(DISTINCT m.groupId) AS groups, count(*) AS artifacts
WITH bootVersion, mine, boots, groups, artifacts, reduce(m = head(groups), g IN groups | CASE WHEN g < m THEN g ELSE m END) AS first
RETURN 'override:' + mine + ':' + boots + ':' + first AS id, 'medium' AS severity, 'dependencies' AS category,
       first + CASE WHEN size(groups) > 1 THEN ' and ' + toString(size(groups) - 1) + ' related group(s)' ELSE '' END
         + ' pinned to ' + mine + ' (Spring Boot ' + bootVersion + ' manages ' + boots + ')' AS title,
       'Overrides ' + toString(artifacts) + ' managed artifact(s) in ' + reduce(s = '', g IN groups[0..5] | s + CASE WHEN s = '' THEN '' ELSE ', ' END + g)
         + '. Patches Spring Boot ships for them do not reach this build.' AS detail,
       'Remove the version override and take ' + boots + ' from Spring Boot, unless you pinned it on purpose (then note why).' AS fix,
       'pom.xml' AS file, 0 AS line, null AS link
VulnerableDependencies — One finding per vulnerable dependency rather than per advisory: how many advisories affect the exact version resolved, the worst CVSS, and the one upgrade on your own line (same major.minor) that fixes every advisory that has a fix there — the unit of work a developer actually does.
MATCH (p:JavaProject {key: $project})-[:DEPENDS_ON]->(d:ProjectDependency)
WHERE d.depth > 0 AND size(split(d.coordinates, ':')) = 3
WITH DISTINCT d.coordinates AS coordinates, d.version AS version, d.groupId + ':' + d.artifactId AS artifact, head(collect(d)) AS d
MATCH (d)-[:HAS_ADVISORY]->(a:DependencyAdvisory)-[:DESCRIBED_BY]->(x:AdvisoryDetail)
OPTIONAL MATCH (a)-[:FIXED_IN]->(f:AdvisoryFix)
WITH coordinates, version, artifact, a, x, collect(f.fixed) AS fixes, split(version, '.')[0] + '.' + split(version, '.')[1] AS line
OPTIONAL MATCH (:PublishedArtifact {ga: artifact})-[:PUBLISHED]->(pv:PublishedVersion)
WITH coordinates, version, artifact, a, x, fixes, line, collect(pv.version) AS published
WITH coordinates, version, artifact, a, x, line, published,
     [v IN fixes WHERE split(v, '.')[0] + '.' + split(v, '.')[1] = line][0] AS onLine
WITH coordinates, version, artifact, line, published, count(a) AS advisories, max(x.cvss3Score) AS worst,
     collect(onLine) AS onLineFixes, collect(CASE WHEN x.cvss3Score >= 9 THEN 1 END) AS crit
WITH coordinates, version, artifact, line, advisories, worst, size([c IN crit WHERE c IS NOT NULL]) AS critical,
     [v IN onLineFixes WHERE v IS NOT NULL] AS fixed, [v IN onLineFixes WHERE v IS NOT NULL AND v IN published] AS downloadable,
     size(published) > 0 AS knowsPublished
WITH coordinates, version, artifact, line, advisories, worst, critical, fixed, downloadable, knowsPublished,
     reduce(best = null, v IN (CASE WHEN knowsPublished THEN downloadable ELSE fixed END) |
       CASE WHEN best IS NULL OR [n IN [x IN split(v, '.') | toInteger(x)] WHERE n IS NOT NULL] > [n IN [x IN split(best, '.') | toInteger(x)] WHERE n IS NOT NULL] THEN v ELSE best END) AS upgradeTo,
     reduce(best = null, v IN fixed |
       CASE WHEN best IS NULL OR [n IN [x IN split(v, '.') | toInteger(x)] WHERE n IS NOT NULL] > [n IN [x IN split(best, '.') | toInteger(x)] WHERE n IS NOT NULL] THEN v ELSE best END) AS anyFix
WITH coordinates, version, artifact, line, advisories, worst, critical, upgradeTo, anyFix, size(fixed) AS fixedOnLine,
     CASE WHEN upgradeTo IS NULL THEN 0 ELSE size([v IN fixed WHERE [n IN [x IN split(v, '.') | toInteger(x)] WHERE n IS NOT NULL] <= [n IN [x IN split(upgradeTo, '.') | toInteger(x)] WHERE n IS NOT NULL]]) END AS coveredBy
RETURN 'vulnerable:' + coordinates AS id,
       CASE WHEN worst >= 9 THEN 'critical' WHEN worst >= 7 THEN 'high' WHEN worst >= 4 THEN 'medium' ELSE 'low' END AS severity,
       'vulnerability' AS category,
       artifact + ' ' + version + ': ' + toString(advisories) + ' advisor' + CASE WHEN advisories = 1 THEN 'y' ELSE 'ies' END
         + CASE WHEN critical > 0 THEN ' (' + toString(critical) + ' critical)' ELSE '' END AS title,
       'Worst CVSS ' + toString(worst) + '. ' + toString(fixedOnLine) + ' of ' + toString(advisories) + ' are fixed on your ' + line + ' line'
         + CASE WHEN anyFix IS NOT NULL AND anyFix <> coalesce(upgradeTo, '') THEN '; the fix in ' + anyFix + ' is a commercial-only release, not on Maven Central' ELSE '' END + '.' AS detail,
       CASE WHEN upgradeTo IS NOT NULL THEN 'Upgrade to ' + upgradeTo + ' — fixes ' + toString(coveredBy) + ' of ' + toString(advisories)
              + CASE WHEN coveredBy < advisories THEN '; the rest need a newer line (see the Upgrade tab).' ELSE '.' END
            WHEN anyFix IS NOT NULL THEN 'No downloadable fix on your ' + line + ' line (' + anyFix + ' is commercial-only): move to a newer line (see the Upgrade tab).'
            ELSE 'No fix on your ' + line + ' line: move to a newer line (see the Upgrade tab).' END AS fix,
       coordinates AS file, 0 AS line, null AS link, worst AS cvss, advisories, upgradeTo
ORDER BY cvss DESC LIMIT 500
GradleStackCard — StackCard for a GRADLE project whose build file is build.gradle.kts (the Kotlin DSL): the Spring Boot version its plugins block applies, the Boot line and when that line's open-source and commercial support end, the Java versions the line supports, its latest patch, and the newest line. Use it when StackCard returns no Boot version because the project has no pom.xml. Read from the build file as written: a version held in a variable, a version catalogue or a settings plugin is not followed, and a Groovy build.gradle is not read. Spring Framework's version is not given (Boot manages it).
MATCH (p:JavaProject {key: $project})-[:BUILD_CALLS]->(c:SpringBuildCall)
WHERE c.method = 'plugins' AND (c.path = 'build.gradle.kts' OR c.path ENDS WITH '/build.gradle.kts') AND c.arguments[0] CONTAINS 'org.springframework.boot") version "'
WITH split(split(c.arguments[0], 'org.springframework.boot") version "')[1], '"')[0] AS bootVersion, c.path AS path ORDER BY size(path) LIMIT 1
WITH bootVersion, null AS frameworkVersion
WITH bootVersion, frameworkVersion, split(bootVersion, '.')[0] + '.' + split(bootVersion, '.')[1] AS line
MATCH (sp:SpringProduct {slug: 'spring-boot'})-[:HAS_GENERATION]->(g:SpringGeneration)
WITH bootVersion, frameworkVersion, line, sp, collect(g) AS gens, toString(date()) AS today

       p.modules AS modules, p.analysedAt AS analysedAt, p.failed AS failed
ORDER BY analysedAt DESC LIMIT 200
ModuleSources — Each Maven module of a project with how many source files it holds, main and test, and in which languages. The first step down from a project: pick a module, then ask ModulePackages.
MATCH (p:JavaProject {key: $project})-[:HAS_MODULE]->(m:ProjectModule)
OPTIONAL MATCH (p)-[:HAS_FILE]->(f:ProjectFile)
WHERE f.module = m.module AND f.extension IN ['java', 'kt', 'kts', 'groovy', 'scala'] AND ('/' + f.path) CONTAINS '/src/'
WITH m, f, split(split('/' + f.path, '/src/')[1], '/')[0] AS sourceSet
RETURN m.module AS module, m.coordinates AS coordinates, m.packaging AS packaging, m.name AS name,
       count(CASE WHEN sourceSet = 'main' THEN 1 END) AS mainFiles,
       count(CASE WHEN sourceSet = 'test' THEN 1 END) AS testFiles,
       [x IN collect(DISTINCT f.extension) WHERE x IS NOT NULL] AS languages
ORDER BY mainFiles DESC, module LIMIT 500
ModulePackages — The packages of one Maven module, by source set (main, test), with how many source files each holds and in which languages. A package is the directory under `src/<set>/<language>/`.
MATCH (p:JavaProject {key: $project})-[:HAS_FILE]->(f:ProjectFile)
WHERE f.module = $module AND f.extension IN ['java', 'kt', 'kts', 'groovy', 'scala'] AND ('/' + f.path) CONTAINS '/src/'
WITH f, split(split('/' + f.path, '/src/')[1], '/') AS parts
WITH parts[0] AS sourceSet, f,
     reduce(s = '', x IN parts[2..size(parts) - 1] | CASE WHEN s = '' THEN x ELSE s + '.' + x END) AS package
RETURN package, sourceSet, count(f) AS files, collect(DISTINCT f.extension) AS languages
ORDER BY sourceSet, package LIMIT 3000
PackageFiles — The source files of one package in one module and source set, each with a link to it on the repository's host.
MATCH (p:JavaProject {key: $project})-[:HAS_FILE]->(f:ProjectFile)
WHERE f.module = $module AND f.extension IN ['java', 'kt', 'kts', 'groovy', 'scala'] AND ('/' + f.path) CONTAINS '/src/'
WITH f, split(split('/' + f.path, '/src/')[1], '/') AS parts
WITH f, parts[0] AS sourceSet,
     reduce(s = '', x IN parts[2..size(parts) - 1] | CASE WHEN s = '' THEN x ELSE s + '.' + x END) AS package
WHERE package = $package AND sourceSet = $sourceSet
RETURN f.fileName AS file, f.extension AS language, f.path AS path, f.link AS link
ORDER BY file LIMIT 2000
FilesByExtension — What a project is written in: its files counted by extension, with how many are under src/main and src/test and how many modules hold them. Every file is counted, not only JVM source, so a build with TypeScript, Python or templates beside its Kotlin and Java shows them.
MATCH (p:JavaProject {key: $project})-[:HAS_FILE]->(f:ProjectFile)
WHERE f.extension IS NOT NULL AND f.extension <> ''
WITH f.extension AS extension, f,
     CASE WHEN ('/' + f.path) CONTAINS '/src/test/' THEN 'test' WHEN ('/' + f.path) CONTAINS '/src/main/' THEN 'main' ELSE 'other' END AS place
RETURN extension, count(f) AS files,
       count(CASE WHEN place = 'main' THEN 1 END) AS mainFiles,
       count(CASE WHEN place = 'test' THEN 1 END) AS testFiles,
       count(DISTINCT f.module) AS modules
ORDER BY files DESC LIMIT 80

What an empty panel means

An empty finding list means the rule ran and found nothing — but only over what could be read. A project with no root pom.xml (a Gradle build) has no build to resolve, so the Spring Boot version, dependencies, configuration checks and upgrade path stay empty; its code findings still appear. A module whose POM is missing, a file that does not parse, or a source that could not be reached comes back as a warning from the view, never as silence. Kotlin source is not read yet. "No fixed version is published yet" means OSV lists none, not that there is no risk.

What the appliance did that a conventional stack could not

Every panel is a query over one graph that spans your code, your build and the outside world at once: a dependency Maven resolved for your project joins straight to the advisories that name its exact version, a setting in your YAML joins to the property Spring Boot's own jar documents, and a Spring Boot release's BOM joins to the jars that say what that release removed — each read live when the query reaches it, with no ingestion pipeline, no database of your code, and no API glue written for this page. The same views answer your coding agent over MCP and your questions in chat.
