Spring Stack Report

What your Spring app runs on, what blocks the next upgrade, what is vulnerable — every finding linked to its line.

How it works

The data, and how fresh it is

Nothing about your project is stored. Each time you analyze it, the appliance reads it where it lives: a GitHub repository at the commit its branch or tag points to now (cloned once, then kept by commit — a commit never changes), or a folder of yours, read afresh every time. Its Java source and its application settings are parsed in place; its Maven build is resolved by Maven's own resolver, every module against the others, against Maven Central. Support dates come from spring.io and endoflife.date (cached a day); advisories from deps.dev and the fixed versions from OSV (cached a day, a week for a published version). Which properties Spring Boot binds, deprecates and removed comes from the configuration metadata inside Spring Boot's own jars, for the version you run and the version you upgrade to. Your decisions in the debt inbox are the one thing kept, as SpringTriage entries in your world.

Every view, with the Cypher that runs

StackCard — What a Spring project runs on: its Spring Boot and Spring Framework versions, the Boot line and when that line's open-source and commercial support end, the Java versions the line supports, its latest patch, and the newest Spring Boot line. The first call for a Spring project.
MATCH (p:JavaProject {key: $project})-[:DEPENDS_ON]->(d:ProjectDependency)
WHERE (d.groupId = 'org.springframework.boot' AND d.artifactId = 'spring-boot')
   OR (d.groupId = 'org.springframework' AND d.artifactId = 'spring-core')
WITH collect(DISTINCT CASE WHEN d.artifactId = 'spring-boot' THEN d.version END) AS boots,
     collect(DISTINCT CASE WHEN d.artifactId = 'spring-core' THEN d.version END) AS cores
WITH [v IN boots WHERE v IS NOT NULL][0] AS bootVersion, [v IN cores WHERE v IS NOT NULL][0] AS frameworkVersion
WITH bootVersion, frameworkVersion, split(bootVersion, '.')[0] + '.' + split(bootVersion, '.')[1] AS line
MATCH (sp:SpringProduct {slug: 'spring-boot'})-[:HAS_GENERATION]->(g:SpringGeneration)
WITH bootVersion, frameworkVersion, line, sp, collect(g) AS gens, toString(date()) AS today
MATCH (sp)-[:HAS_CYCLE]->(c:SupportCycle)
WITH bootVersion, frameworkVersion, line, gens, today, collect(c) AS cycles
WITH bootVersion, frameworkVersion, line, today,
     [x IN gens WHERE x.name = line + '.x'][0] AS mine,
     [x IN cycles WHERE x.cycle = line][0] AS myCycle,
     reduce(n = null, x IN gens | CASE WHEN x.initialReleaseDate <= today
            AND (n IS NULL OR x.initialReleaseDate > n.initialReleaseDate) THEN x ELSE n END) AS newest
RETURN bootVersion, frameworkVersion, line + '.x' AS bootLine,
       mine.ossSupportEndDate AS ossSupportEnds, mine.commercialSupportEndDate AS commercialSupportEnds,
       CASE WHEN mine IS NULL THEN 'unknown'
            WHEN mine.ossSupportEndDate >= today THEN 'supported'
            WHEN mine.commercialSupportEndDate >= today THEN 'commercial-only'
            ELSE 'unsupported' END AS support,
       myCycle.supportedJavaVersions AS javaVersions, myCycle.latest AS latestPatch,
       newest.name AS newestLine, newest.ossSupportEndDate AS newestSupportEnds
BootLines — Every Spring Boot line: when its open-source and commercial support end, the Java versions it supports, and its latest patch — what to upgrade to, and what that asks of your Java.
MATCH (sp:SpringProduct {slug: 'spring-boot'})-[:HAS_GENERATION]->(g:SpringGeneration)
WITH sp, g, toString(date()) AS today
OPTIONAL MATCH (sp)-[:HAS_CYCLE]->(c:SupportCycle)
WHERE c.cycle + '.x' = g.name
RETURN g.name AS line, g.initialReleaseDate AS released, g.ossSupportEndDate AS ossSupportEnds,
       g.commercialSupportEndDate AS commercialSupportEnds, c.latest AS latestPatch, c.supportedJavaVersions AS javaVersions,
       CASE WHEN g.initialReleaseDate > today THEN 'upcoming'
            WHEN g.ossSupportEndDate >= today THEN 'supported'
            WHEN g.commercialSupportEndDate >= today THEN 'commercial-only'
            ELSE 'unsupported' END AS support
ORDER BY released DESC LIMIT 40
ModernizationFindings — Code Spring has moved past, with what to write instead: javax packages Jakarta EE renamed, WebSecurityConfigurerAdapter, field injection, @MockBean and @SpyBean, JUnit 4, the old @ConstructorBinding, RestTemplate, and auto-configuration registered in spring.factories. Each links to its line.
MATCH (p:JavaProject {key: $project})-[:HAS_IMPORT]->(i:JavaProjectImport)
WHERE i.name STARTS WITH 'javax.persistence' OR i.name STARTS WITH 'javax.servlet'
   OR i.name STARTS WITH 'javax.validation' OR i.name STARTS WITH 'javax.annotation.PostConstruct'
   OR i.name STARTS WITH 'javax.annotation.PreDestroy' OR i.name STARTS WITH 'javax.transaction'
   OR i.name STARTS WITH 'javax.inject' OR i.name STARTS WITH 'javax.ws.rs' OR i.name STARTS WITH 'javax.mail'
   OR i.name STARTS WITH 'javax.jms' OR i.name STARTS WITH 'javax.websocket'
RETURN 'jakarta:' + i.path + ':' + toString(i.line) AS id, 'high' AS severity, 'upgrade-blocker' AS category,
       'javax → jakarta: ' + i.name AS title,
       'Spring Boot 3 / Spring Framework 6 use Jakarta EE 9+, where javax.* became jakarta.*. This import does not compile there.' AS detail,
       'import ' + replace(i.name, 'javax.', 'jakarta.') + ' (OpenRewrite recipe org.openrewrite.java.migrate.jakarta.JavaxMigrationToJakarta)' AS fix,
       i.path AS file, i.line AS line, i.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:DECLARES_TYPE]->(t:JavaProjectType)
WHERE ANY(s IN t.extends WHERE s ENDS WITH 'WebSecurityConfigurerAdapter' OR s ENDS WITH 'WebMvcConfigurerAdapter')
RETURN 'adapter:' + t.name AS id, 'high' AS severity, 'upgrade-blocker' AS category,
       t.simpleName + ' extends ' + [s IN t.extends WHERE s ENDS WITH 'Adapter'][0] AS title,
       CASE WHEN ANY(s IN t.extends WHERE s ENDS WITH 'WebSecurityConfigurerAdapter')
            THEN 'WebSecurityConfigurerAdapter was removed in Spring Security 6 (Spring Boot 3).'
            ELSE 'WebMvcConfigurerAdapter was removed in Spring Framework 6.' END AS detail,
       CASE WHEN ANY(s IN t.extends WHERE s ENDS WITH 'WebSecurityConfigurerAdapter')
            THEN 'Declare a @Bean SecurityFilterChain filterChain(HttpSecurity http) instead (OpenRewrite recipe org.openrewrite.java.spring.security5.WebSecurityConfigurerAdapter)'
            ELSE 'implement WebMvcConfigurer directly' END AS fix,
       t.path AS file, t.line AS line, t.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:HAS_ANNOTATION]->(a:JavaProjectAnnotation {name: 'Autowired', targetKind: 'field'})
RETURN 'field-injection:' + a.owner + '#' + a.targetName AS id, 'medium' AS severity, 'design' AS category,
       'Field injection: ' + a.owner + '.' + a.targetName AS title,
       'An @Autowired field hides a dependency, cannot be final, and needs a container to test.' AS detail,
       'Take it as a constructor parameter (a single constructor needs no @Autowired).' AS fix,
       a.path AS file, a.line AS line, a.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:HAS_ANNOTATION]->(a:JavaProjectAnnotation)
WHERE a.name IN ['MockBean', 'SpyBean']
RETURN 'mockbean:' + a.path + ':' + toString(a.line) AS id, 'medium' AS severity, 'upgrade-blocker' AS category,
       '@' + a.name + ' on ' + a.targetName AS title,
       '@MockBean and @SpyBean were deprecated in Spring Boot 3.4 and removed in 4.0.' AS detail,
       'Use @MockitoBean / @MockitoSpyBean (org.springframework.test.context.bean.override.mockito).' AS fix,
       a.path AS file, a.line AS line, a.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:HAS_IMPORT]->(i:JavaProjectImport)
WHERE i.name IN ['org.junit.Test', 'org.junit.runner.RunWith', 'org.junit.Before', 'org.junit.After', 'org.junit.Assert']
RETURN 'junit4:' + i.path + ':' + toString(i.line) AS id, 'medium' AS severity, 'testing' AS category,
       'JUnit 4: ' + i.name AS title,
       'Spring Boot 2.4+ ships JUnit 5 only; JUnit 4 tests need the vintage engine, which Boot 3 no longer manages.' AS detail,
       'Move to org.junit.jupiter (OpenRewrite recipe org.openrewrite.java.testing.junit5.JUnit4to5Migration)' AS fix,
       i.path AS file, i.line AS line, i.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:HAS_IMPORT]->(i:JavaProjectImport {name: 'org.springframework.boot.context.properties.ConstructorBinding'})
RETURN 'constructor-binding:' + i.path AS id, 'medium' AS severity, 'upgrade-blocker' AS category,
       'Old @ConstructorBinding in ' + i.path AS title,
       'Spring Boot 3 moved it to org.springframework.boot.context.properties.bind.ConstructorBinding and no longer needs it on a class with one constructor.' AS detail,
       'Remove it from the class; keep it, from the new package, only to pick one of several constructors.' AS fix,
       i.path AS file, i.line AS line, i.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:HAS_IMPORT]->(i:JavaProjectImport {name: 'org.springframework.web.client.RestTemplate'})
RETURN 'resttemplate:' + i.path AS id, 'info' AS severity, 'modernize' AS category,
       'RestTemplate in ' + i.path AS title,
       'RestTemplate is in maintenance; Spring Framework 6.1 added RestClient, the same synchronous model with a fluent API.' AS detail,
       'Build a RestClient (RestClient.create() or RestClient.Builder) for new code.' AS fix,
       i.path AS file, i.line AS line, i.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:HAS_FILE]->(f:ProjectFile {fileName: 'spring.factories'})
WHERE f.path CONTAINS 'src/main/resources/META-INF/'
RETURN 'spring-factories:' + f.path AS id, 'medium' AS severity, 'upgrade-blocker' AS category,
       'META-INF/spring.factories in ' + coalesce(nullif(f.module, ''), 'the root module') AS title,
       'Spring Boot 3 no longer reads auto-configurations from spring.factories; any EnableAutoConfiguration entry in it is ignored.' AS detail,
       'Move each auto-configuration to META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports and annotate it @AutoConfiguration.' AS fix,
       f.path AS file, 1 AS line, f.link AS link
ConfigurationProblems — Settings in the project's application*.yml / .properties that the Spring Boot it runs does not bind (a typo, or a property from another version), and settings it has deprecated — checked against what the project's own Spring Boot jars document. Keys under the project's own @ConfigurationProperties prefixes, or read by @Value, are the project's and are not flagged. Downloads the project's Spring Boot jars the first time.
MATCH (p:JavaProject {key: $project})-[:HAS_JAR]->(j:ProjectJar)
WHERE j.groupId = 'org.springframework.boot' AND j.jarPath IS NOT NULL
MATCH (j)-[:DOCUMENTS]->(bp:BootProperty)
WITH p, collect(bp) AS props
WITH p, props, [x IN props | x.name] AS known,
     [x IN props WHERE x.type STARTS WITH 'java.util.Map' OR x.type STARTS WITH 'java.util.List' | x.name] AS open
OPTIONAL MATCH (p)-[:HAS_ANNOTATION]->(cp:JavaProjectAnnotation)
WHERE cp.name = 'ConfigurationProperties' OR cp.name = 'Value'
WITH p, props, known, open,
     collect(DISTINCT CASE WHEN cp.name = 'ConfigurationProperties'
               THEN coalesce([x IN cp.attributes WHERE x STARTS WITH 'prefix=' | substring(x, 7)][0], cp.value) END) AS ownPrefixes,
     collect(DISTINCT CASE WHEN cp.name = 'Value' THEN split(split(split(cp.value, '${')[1], '}')[0], ':')[0] END) AS valueKeys
MATCH (p)-[:HAS_SETTING]->(s:ProjectSetting)
WHERE s.path CONTAINS 'src/main/resources' AND (s.fileName STARTS WITH 'application' OR s.fileName STARTS WITH 'bootstrap')
  AND NOT s.name IN ['spring.config.activate.on-profile', 'spring.profiles']
WITH s, props, known, open, [x IN ownPrefixes WHERE x IS NOT NULL] AS ownPrefixes, [x IN valueKeys WHERE x IS NOT NULL] AS valueKeys,
     split(s.name, '[')[0] AS base
WITH s, base, ownPrefixes, valueKeys, known, open, [x IN props WHERE x.name = base][0] AS match
WHERE NOT ANY(x IN ownPrefixes WHERE base STARTS WITH x + '.' OR base = x)
  AND NOT ANY(x IN valueKeys WHERE base = x)
  AND NOT ANY(x IN open WHERE base STARTS WITH x + '.')
  AND (match IS NULL OR match.deprecated)
RETURN 'config:' + s.path + ':' + toString(s.line) + ':' + s.name AS id,
       CASE WHEN match IS NULL THEN 'medium' WHEN match.deprecationLevel = 'error' THEN 'high' ELSE 'low' END AS severity,
       'configuration' AS category,
       CASE WHEN match IS NULL THEN 'Spring Boot binds no property ' + s.name
            WHEN match.deprecationLevel = 'error' THEN s.name + ' no longer binds'
            ELSE s.name + ' is deprecated' END AS title,
       CASE WHEN match IS NULL THEN 'Nothing in the Spring Boot jars this project resolves documents it, and no @ConfigurationProperties or @Value of the project reads it: a typo, or a property from another Spring Boot version, does nothing.'
            WHEN match.deprecationLevel = 'error' THEN 'Spring Boot removed it' + coalesce(' in ' + match.deprecatedSince, '') + ': the setting is silently ignored.' + coalesce(' ' + match.deprecationReason, '')
            ELSE coalesce(match.deprecationReason, 'Deprecated') + coalesce(' (since ' + match.deprecatedSince + ')', '') + '; it still binds, for now.' END AS detail,
       CASE WHEN match IS NULL THEN 'Check the spelling against the Spring Boot reference, or remove it.'
            WHEN match.replacement IS NOT NULL THEN 'Use ' + match.replacement + ' instead.'
            ELSE 'Remove it.' END AS fix,
       s.path AS file, s.line AS line, s.link AS link
LIMIT 500
UpgradeConfiguration — Settings in the project that the target Spring Boot version removed or renamed, each with the property to use there — read from the target release's own jars, which document every property they dropped with its replacement. `target` is a Spring Boot version, e.g. 3.5.16 or 4.1.2. Downloads the target's Spring Boot jars the first time.
MATCH (bom:BootBom {coordinates: 'org.springframework.boot:spring-boot-dependencies:' + $target})-[:PINS]->(v:BootManagedVersion)
WHERE v.groupId = 'org.springframework.boot' AND v.artifactId STARTS WITH 'spring-boot'
  AND NOT v.artifactId CONTAINS 'starter' AND NOT v.artifactId CONTAINS 'test' AND NOT v.artifactId ENDS WITH '-docs'
MATCH (v)-[:IS]->(b:BootJar)-[:DOCUMENTS]->(bp:BootProperty)
WHERE bp.deprecated
WITH collect(bp) AS dropped
MATCH (p:JavaProject {key: $project})-[:HAS_SETTING]->(s:ProjectSetting)
WHERE s.path CONTAINS 'src/main/resources' AND (s.fileName STARTS WITH 'application' OR s.fileName STARTS WITH 'bootstrap')
WITH s, [x IN dropped WHERE x.name = split(s.name, '[')[0]][0] AS match
WHERE match IS NOT NULL
RETURN 'upgrade-config:' + $target + ':' + s.path + ':' + toString(s.line) + ':' + s.name AS id,
       CASE WHEN match.deprecationLevel = 'error' THEN 'high' ELSE 'low' END AS severity,
       'upgrade-blocker' AS category,
       CASE WHEN match.deprecationLevel = 'error' THEN s.name + ' is gone in Spring Boot ' + $target
            ELSE s.name + ' is deprecated in Spring Boot ' + $target END AS title,
       coalesce(match.deprecationReason + '. ', '') + CASE WHEN match.deprecationLevel = 'error' THEN 'It no longer binds there: the setting is silently ignored.' ELSE 'It still binds, for now.' END AS detail,
       CASE WHEN match.replacement IS NOT NULL THEN 'Rename it to ' + match.replacement + '.' ELSE 'Remove it.' END AS fix,
       s.path AS file, s.line AS line, s.link AS link
LIMIT 500
Vulnerabilities — Security advisories affecting the exact versions the project resolves, worst first: the dependency, the advisory and its CVE ids, its CVSS score, and the fixed version on your own line (same major.minor) when there is one — else the nearest fix above it.
MATCH (p:JavaProject {key: $project})-[:DEPENDS_ON]->(d:ProjectDependency)
WHERE d.depth > 0
WITH DISTINCT d.coordinates AS coordinates, d.version AS version, d.groupId + ':' + d.artifactId AS artifact, head(collect(d)) AS d
MATCH (d)-[:HAS_ADVISORY]->(a:DependencyAdvisory)-[:DESCRIBED_BY]->(x:AdvisoryDetail)
OPTIONAL MATCH (a)-[:FIXED_IN]->(f:AdvisoryFix)
WITH coordinates, version, artifact, a, x, collect(f.fixed) AS fixes,
     split(version, '.')[0] + '.' + split(version, '.')[1] AS line
WITH coordinates, version, artifact, a, x, fixes, line,
     [v IN fixes WHERE split(v, '.')[0] + '.' + split(v, '.')[1] = line][0] AS onLine
RETURN 'cve:' + coordinates + ':' + a.advisoryId AS id,
       CASE WHEN x.cvss3Score >= 9 THEN 'critical' WHEN x.cvss3Score >= 7 THEN 'high' WHEN x.cvss3Score >= 4 THEN 'medium' ELSE 'low' END AS severity,
       'vulnerability' AS category,
       artifact + ' ' + version + ': ' + x.title AS title,
       a.advisoryId + coalesce(' / ' + [y IN x.aliases WHERE y STARTS WITH 'CVE-'][0], '') + ', CVSS ' + toString(x.cvss3Score) AS detail,
       CASE WHEN onLine IS NOT NULL THEN 'Upgrade to ' + onLine + ' (same line).'
            WHEN size(fixes) > 0 THEN 'Fixed in ' + reduce(s = '', v IN fixes | s + CASE WHEN s = '' THEN '' ELSE ', ' END + v) + ' — no fix on your ' + line + ' line.'
            ELSE 'No fixed version is published yet.' END AS fix,
       coordinates AS file, 0 AS line, x.url AS link, x.cvss3Score AS cvss
ORDER BY cvss DESC LIMIT 500
VersionOverrides — Where the project's build pins a different version than the Spring Boot it runs would — a `<jackson-bom.version>` property, a hand-written version on a managed dependency — so a patch Spring Boot ships for it never arrives. Compared against the Spring Boot release's own BOM.
MATCH (p:JavaProject {key: $project})-[:DEPENDS_ON]->(boot:ProjectDependency)
WHERE boot.groupId = 'org.springframework.boot' AND boot.artifactId = 'spring-boot'
WITH p, head(collect(boot.version)) AS bootVersion
MATCH (bom:BootBom {coordinates: 'org.springframework.boot:spring-boot-dependencies:' + bootVersion})-[:PINS]->(v:BootManagedVersion)
WITH p, bootVersion, collect(v) AS pins
MATCH (p)-[:MANAGES]->(m:ProjectManagedVersion)
WITH bootVersion, m, [x IN pins WHERE x.groupId = m.groupId AND x.artifactId = m.artifactId][0] AS pin
WHERE pin IS NOT NULL AND pin.version <> m.version
WITH bootVersion, m.version AS mine, pin.version AS boots, collect(DISTINCT m.groupId) AS groups, count(*) AS artifacts
WITH bootVersion, mine, boots, groups, artifacts, reduce(m = head(groups), g IN groups | CASE WHEN g < m THEN g ELSE m END) AS first
RETURN 'override:' + mine + ':' + boots + ':' + first AS id, 'medium' AS severity, 'dependencies' AS category,
       first + CASE WHEN size(groups) > 1 THEN ' and ' + toString(size(groups) - 1) + ' related group(s)' ELSE '' END
         + ' pinned to ' + mine + ' (Spring Boot ' + bootVersion + ' manages ' + boots + ')' AS title,
       'Overrides ' + toString(artifacts) + ' managed artifact(s) in ' + reduce(s = '', g IN groups[0..5] | s + CASE WHEN s = '' THEN '' ELSE ', ' END + g)
         + '. Patches Spring Boot ships for them do not reach this build.' AS detail,
       'Remove the version override and take ' + boots + ' from Spring Boot, unless you pinned it on purpose (then note why).' AS fix,
       'pom.xml' AS file, 0 AS line, null AS link
Beans — Every bean the project's source declares: classes annotated @Component, @Service, @Repository, @Controller, @RestController or @Configuration, and @Bean methods — each with the profiles and conditions it is declared under, and a link to its line. What the source says; a running app's RuntimeBeans says what was actually created.
MATCH (p:JavaProject {key: $project})-[:HAS_ANNOTATION]->(a:JavaProjectAnnotation)
WHERE a.name IN ['Component', 'Service', 'Repository', 'Controller', 'RestController', 'Configuration', 'Bean', 'ControllerAdvice', 'RestControllerAdvice']
WITH p, a
OPTIONAL MATCH (p)-[:HAS_ANNOTATION]->(o:JavaProjectAnnotation)
WHERE (o.targetId = a.targetId OR (a.targetKind = 'method' AND o.targetKind = 'type' AND o.targetName = a.owner))
  AND (o.name = 'Profile' OR o.name STARTS WITH 'Conditional')
WITH a, collect(DISTINCT CASE WHEN o.name = 'Profile' THEN o.value END) AS profiles,
     collect(DISTINCT CASE WHEN o.name STARTS WITH 'Conditional' THEN o.text END) AS conditions
RETURN CASE WHEN a.name = 'Bean' THEN a.owner + '#' + a.targetName ELSE a.targetName END AS bean,
       CASE WHEN a.name = 'Bean' THEN '@Bean method' ELSE '@' + a.name END AS declaredBy,
       [x IN profiles WHERE x IS NOT NULL] AS profiles, [x IN conditions WHERE x IS NOT NULL] AS conditions,
       a.module AS module, a.path AS file, a.line AS line, a.link AS link
ORDER BY declaredBy, bean LIMIT 2000
Profiles — Every Spring profile the project uses and where: @Profile on classes and @Bean methods, application-<profile> files, and YAML documents activated on a profile.
MATCH (p:JavaProject {key: $project})-[:HAS_ANNOTATION]->(a:JavaProjectAnnotation {name: 'Profile'})
UNWIND a.values AS profile
RETURN profile, 'code' AS where, coalesce(a.owner + '#' + a.targetName, a.targetName) AS what, a.path AS file, a.line AS line, a.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:HAS_FILE]->(f:ProjectFile)
WHERE f.fileName STARTS WITH 'application-' AND f.extension IN ['yml', 'yaml', 'properties']
RETURN split(split(f.fileName, 'application-')[1], '.')[0] AS profile, 'file' AS where, f.fileName AS what, f.path AS file, 1 AS line, f.link AS link
UNION
MATCH (p:JavaProject {key: $project})-[:HAS_SETTING]->(s:ProjectSetting)
WHERE s.name IN ['spring.config.activate.on-profile', 'spring.profiles']
RETURN s.value AS profile, 'document' AS where, s.fileName + ' document ' + toString(s.document) AS what, s.path AS file, s.line AS line, s.link AS link
Triage — What has been decided about this project's findings: done, snoozed or won't fix, with notes.
MATCH (t:SpringTriage {project: $project})
RETURN t.findingId AS findingId, t.status AS status, t.title AS title, t.note AS note
LIMIT 2000
WhyNotApplied — Why each auto-configuration or @Bean method did NOT apply in a running app, in Spring's own words — "why isn't my bean created". Takes /actuator/conditions.
MATCH (:RunningApp {actuator: $actuator})-[:EVALUATED]->(c:RuntimeCondition {configurationMatched: false, outcome: 'notMatched'})
RETURN c.configuration AS configuration, c.beanMethod AS beanMethod, c.condition AS condition, c.message AS why
ORDER BY configuration LIMIT 2000
RuntimeBeans — The beans a running app actually created — name, the class behind any proxy, scope, where it was defined and what it depends on. Takes /actuator/beans.
MATCH (:RunningApp {actuator: $actuator})-[:HAS_BEAN]->(b:RuntimeBean)
RETURN b.name AS bean, b.targetType AS type, b.scope AS scope, b.resource AS definedIn, b.dependencies AS dependsOn
ORDER BY type LIMIT 5000
EffectiveSettings — For each property in a running app, which property source's value won and where it came from (file and line, environment variable, system property). Takes /actuator/env.
MATCH (:RunningApp {actuator: $actuator})-[:HAS_SETTING]->(s:RuntimeSetting {effective: true})
RETURN s.name AS property, s.value AS value, s.source AS source, s.origin AS origin, s.masked AS masked
ORDER BY property LIMIT 5000
ShippedVulnerabilities — Advisories against what a running app actually shipped, from its SBOM. Takes /actuator/sbom/application.
MATCH (:RunningApp {actuator: $actuator})-[:SHIPS]->(c:RuntimeComponent)-[:HAS_ADVISORY]->(a:DependencyAdvisory)-[:DESCRIBED_BY]->(x:AdvisoryDetail)
RETURN c.coordinates AS component, a.advisoryId AS advisory, [y IN x.aliases WHERE y STARTS WITH 'CVE-'][0] AS cve,
       x.cvss3Score AS cvss, x.title AS title, x.url AS link
ORDER BY cvss DESC LIMIT 1000

What an empty panel means

An empty finding list means the rule ran and found nothing — but only over what could be read. A project with no root pom.xml (a Gradle build) has no build to resolve, so the Spring Boot version, dependencies, configuration checks and upgrade path stay empty; its code findings still appear. A module whose POM is missing, a file that does not parse, or a source that could not be reached comes back as a warning from the view, never as silence. Kotlin source is not read yet. "No fixed version is published yet" means OSV lists none, not that there is no risk.

What the appliance did that a conventional stack could not

Every panel is a query over one graph that spans your code, your build and the outside world at once: a dependency Maven resolved for your project joins straight to the advisories that name its exact version, a setting in your YAML joins to the property Spring Boot's own jar documents, and a Spring Boot release's BOM joins to the jars that say what that release removed — each read live when the query reaches it, with no ingestion pipeline, no database of your code, and no API glue written for this page. The same views answer your coding agent over MCP and your questions in chat.
